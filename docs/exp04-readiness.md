# 从 EXP03 进入 EXP04 的工程交接

本轮仅准备接入基础，不进行模型选型定案、真实图片发送、额度消费、模型训练或 GPU 部署。

## 已有调用边界

```mermaid
flowchart LR
  U[上传与逻辑页码] --> P[Page 持久化]
  P --> R[Recognizer 接口]
  R --> E[Extractor 抽取与去重]
  E --> C[Clusterer 两级归组]
  C --> O[Markdown 与来源标记]
  O --> V[编辑、保存、历史重开]
  V --> W[Word 导出]
```

接入 AI 时优先替换识别适配器与其结果校验，继续复用上传、存储、抽取、正文与来源恢复、编辑和导出，避免重做已经验证的业务流程。

| 边界 | 当前契约 | 接入时必须保持 |
| --- | --- | --- |
| 上传 | `POST /api/tasks`：multipart `files` 和可选 `order`；201 返回 `task_id/page_count/rejected` | 合法文件顺序决定逻辑页码，拒绝文件不产生页码空洞 |
| 状态 | `GET /api/tasks/{id}`：`status/page_count/error_msg`；`GET .../pages`：页号、文件名、置信度与失败标记 | 任务状态不能代替独立阶段状态；识别成功不等于新大纲已生成 |
| 识别 | `Recognizer.recognize(page_no, file_path)` → `RecognitionResult(text, confidence, low_confidence, structured)` | 结构化 `title/points`；每个 point 含 `content/kp_type/source_type`，校验后再持久化 |
| 抽取 | `Extractor.extract` 与 `dedup_cross_page` | 程序绑定真实页面与来源；相同正文、不同来源类型不能混为一条 |
| 归组 | 规则归组默认；既有模型原型只接受模块名与本次知识点 ID | ID 完整且唯一；正文、类型及全部来源页由程序恢复，模型不得改写 |
| 大纲 | GET/PUT `.../outline`；POST `.../regenerate` | 编辑保存后重开与导出一致；重生成明确确认覆盖；失败保留旧数据 |
| 错误 | `{code, message, retryable}` | 可操作文案，不暴露密钥与服务商内部错误；可重试操作显示明确入口 |

完整字段与路径可从运行中的 `/docs`、`/openapi.json` 查看；Pydantic 数据结构位于 `backend/app/schemas.py`。当前成功响应契约本轮未修改。

## 已准备与仍需完成

已准备：可切换识别接口、独立聚类配置、外置提示词目录、结构化识别存储、来源 ID 保护、HTTP 模拟传输测试、临时数据库隔离和异常注入、前端重试／旧稿保护。

EXP04 开始前需确认以下事项，并以真实证据验收：

1. **场景与数据**：准备有授权的中文课堂照片，包含公式、代码、低清晰度与跨页重复；定义页级期望结果和人工评分口径。
2. **服务与成本**：比较可访问区域、图片支持、结构化输出和实际成本；确认服务商、模型、Base URL、图片使用权限与试调预算。密钥仅放本地 `.env`。
3. **识别契约**：当前多模态原型仍用硬编码提示词、文本行解析和固定置信度，且缺密钥时静默回退 mock。接入时应真正加载版本化 `recognize.yaml`，严格校验输出，明确区分模拟与真实模式，对缺少配置直接报错。
4. **Prompt 与上下文**：图片及课件文字作为待处理数据；保留课堂原文、推断和不确定项的区别；识别使用单页上下文，归组只使用当前任务已保存的知识点与 ID，不跨任务混入资料。
5. **调用与任务可靠性**：补齐识别错误分类、有限重试、真实阶段状态、并发任务控制和持久幂等机制，避免刷新或丢响应造成重复付费调用；明确进程中断后的恢复策略。
6. **可复现实验**：保存模型／提示词版本、脱敏请求标识、耗时、用量和评测结果；先用本地模拟传输跑契约和故障测试，再在确认的小规模样例与预算内真实试调。

本次没有将任何真实模型质量或多课程试用条目标记完成。原始 WBS 的模型质量、性能和 VH1–VH3 目标仍是后续验证工作。
