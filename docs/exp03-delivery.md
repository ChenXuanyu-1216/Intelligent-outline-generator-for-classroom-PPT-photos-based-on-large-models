## 从零运行与检查

依赖和启动命令以[仓库 README](../README.md#快速开始)为准。演示配置必须是 `APP_MODEL_PROVIDER=mock`、`APP_CLUSTER_PROVIDER=rule`。mock 返回预设数据库课程内容，上传其他学科的照片也不会变成真实识别。

安装 `requirements.txt` 与 `requirements-dev.txt` 后，从仓库根目录运行：

```powershell
pwsh -NoProfile -File lecture-syllabus-generator/scripts/verify_exp03.ps1
```

脚本依次运行完整 pytest 和全部前端 Node 测试，任何一组失败都返回非零退出码。Node 只用于检查，正常启动网站不需要 Node 或前端构建。pytest 在导入应用前设置独立临时数据库、上传目录、mock 识别与规则归组，不清空日常数据库，不调用真实 AI 服务。

浏览器演示顺序：

1. 打开 `/`，选择 2–3 张 JPG/PNG，调整顺序并生成；核对进度页的来源页码与提示。
2. 查看大纲，进入编辑，加入一条自己的复习笔记，保存；刷新后应保持相同正文。
3. 导出 Word，核对笔记、来源页码和来源类型；打开历史记录，再次打开同一大纲。
4. 返回该任务的进度页，刷新时应恢复已保存结果，不再触发整批识别和生成。
5. 展开首页或历史页右上角“速度”，拖动或用方向键调速；暂停后调速保持暂停；切换两页仍保持所选速度。

失败、低置信度、额度和网络异常由自动化故障注入覆盖，不需要损坏日常数据或真实消耗模型额度来演示。浏览器正常流程走查与故障注入测试是两种不同证据。

## 本次修复的原因与结果

- 旧进度页在每次打开时直接执行识别和生成，可能覆盖已校对的大纲；现在先读取任务、页级数据与已有大纲，已完成结果直接恢复。
- 旧单页重试之后再次调用整批识别；现在每次重试前重新查询失败页，成功页不重复处理，中途断网后的再次重试也遵循最新页状态。
- 旧页面缺少网络异常恢复；现在显示页内错误与可用的恢复操作，保留编辑草稿和旧大纲。
- 重新生成可能已在服务器完成，但响应或后续读取丢失；大纲页此时禁止导出与再次修改，通过只读查询核对结果，避免预览旧稿却导出新稿。
- 速度独立于播放状态，浏览器可用时通过动画播放速率平滑调整，使用本地存储记住倍率；存储被禁用时仍可当次调速。
- 离线预览由当前 HTML/CSS/JS 生成，避免正式页面与预览分别维护。重建命令：`backend/.venv/Scripts/python.exe scripts/build_frontend_preview.py`（从应用目录执行）。
